# Отклик — платформа доверительных обращений

MVP платформы **анонимных обращений** с умной маршрутизацией к профильным специалистам:
психологам, конфликтологам, юристам, социальным педагогам.

Человек, столкнувшийся с травлей, конфликтом или давлением, может **безопасно и анонимно**
рассказать о ситуации, быстро попасть к нужному специалисту и в любой момент видеть, что
с обращением происходит.

> Тон интерфейса бережный: со школьником сервис говорит на «ты», с родителем и педагогом — на «вы».

## Стек

- **Frontend:** React + TypeScript + Vite + Tailwind CSS (mobile-first, адаптивный)
- **Backend:** Go (стандартная библиотека `net/http`, роутинг Go 1.22)
- **База данных:** PostgreSQL 16
- **Инфраструктура:** Docker + docker-compose, Nginx (раздача SPA + прокси на API)

---

## Запуск одной командой

Требуется установленный **Docker Desktop** (или Docker Engine + docker-compose).

```bash
docker compose up --build
```

После сборки открыть:

- **Приложение (заявитель + вход для сотрудников):** http://localhost:5173
- **API:** http://localhost:8080/api/health

Первая сборка тянет зависимости Go и npm — это может занять пару минут.
База поднимается сама, миграции и тестовые данные применяются автоматически при старте backend.

### Локальный запуск без Docker (для разработки)

```bash
# 1. Postgres (например, в docker)
docker run -e POSTGRES_USER=otklik -e POSTGRES_PASSWORD=otklik -e POSTGRES_DB=otklik -p 5432:5432 postgres:16-alpine

# 2. Backend (нужен Go 1.23+)
cd backend
go mod tidy
go run ./cmd/server        # слушает :8080, сам применит миграции и создаст тестовые аккаунты

# 3. Frontend (нужен Node 20+)
cd frontend
npm install --legacy-peer-deps
npm run dev                # http://localhost:5173, проксирует /api и /uploads на :8080
```

## Роли и что делает каждая

- **Заявитель** — создаёт обращение (анонимно), ведёт диалог, подтверждает/оспаривает результат, оценивает.
- **Оператор** — первая линия: очередь новых, отсев спама/дублей, категория, приоритет, назначение исполнителя.
  Видит **только исходный текст** обращения, переписку заявителя с экспертом не читает.
- **Эксперт** — работает только с назначенными обращениями: чат, уточнения, рекомендации, внутренние заметки,
  соисполнители, запрос передачи. **Не видит личность заявителя** ни на одном этапе.
- **Администратор** — категории и правила маршрутизации, учётки и права, аналитика, разблокировка зависших
  обращений (с причиной и записью в журнал). В переписке не участвует, обращения не закрывает.

## Модель приватности

- Не запрашиваются имя, почта, телефон, учебное заведение — **кроме способа связи**, который
  заявитель по желанию оставляет сам (сценарий кризиса, п. 5.3 ТЗ).
- **IP-адрес и User-Agent не пишутся в БД** и не связываются с обращением. IP используется только
  in-memory для лимита попыток проверки трек-номера и нигде не сохраняется.
- Сторонних трекеров и аналитики нет.
- **Вложения очищаются от метаданных**: изображение декодируется и перекодируется на сервере,
  что удаляет EXIF и геолокацию. Принимаются только изображения (jpg/png/gif), до 5 файлов, до 10 МБ.
- Сессия не связывает обращения одного человека между собой: единственный ключ — трек-номер.
- **Способ связи хранится отдельно** от текста обращения и доступен только оператору по кризисным обращениям.
- В аналитику и выгрузки попадают **только агрегаты и метаданные** — без текстов обращений и переписки
  (CSV содержит id, тип заявителя, категорию, статус, приоритет, кризис-флаг, кол-во возвратов, оценку и тайминги).
- Внутренние заметки экспертов заявителю не видны и визуально отделены от чата.

## Трек-номер (решения)

- Формат `ОТК-XXXX-XXXX`. Алфавит без визуально спорных символов — **без `0/O` и `1/I/L`**
  (`ABCDEFGHJKMNPQRSTUVWXYZ23456789`), 8 значащих символов.
- Генерация криптостойким источником (`crypto/rand`).
- **Открытый номер в базе не хранится** — сохраняется только необратимый хеш `SHA-256(pepper + номер)`.
  Поэтому номер **невозможно восстановить**; при выдаче явно предупреждаем и даём кнопки «Скопировать» и «Сохранить»
  (скачивание `.txt`).
- Защита от перебора: **не более 5 попыток проверки статуса в минуту с адреса**, при превышении — отказ с задержкой.
- Минимизация потери номера: экран выдачи с копированием/сохранением в файл, подсказка добавить страницу
  в закладки, и понятный текст на экране проверки статуса.

## Уведомления (решения)

У анонимного заявителя нет почты и телефона, поэтому реализована модель **«человек возвращается сам»**:

- **Трек-номер + закладка** — основной способ. Заявитель сохраняет номер и сам заходит проверить статус;
  статусы снабжены человеческим пояснением к каждому.
- **Опциональный способ связи** — только для кризисных обращений, с явным согласием и предупреждением,
  что это снижает анонимность; хранится отдельно и доступен только оператору.
- **PWA/push** — заложено как направление развития (см. «Не реализовано»).

## Кризисные обращения

- **Детекция по словарю** (таблица `crisis_keywords`) — по тексту и ответам на уточняющие вопросы.
  Клиент дополнительно показывает контакты помощи сразу при вводе, не прерывая рассказ.
- **Немедленная помощь**: контакты экстренной и кризисной помощи показываются заявителю сразу,
  не блокируя ввод (`GET /api/crisis-contacts`).
- **Приём вне очереди**: у оператора кризисные обращения вынесены отдельным блоком сверху с отсчётом ожидания.
- **Способ связи**: интерфейс отдельно предлагает оставить контакт с пояснением, кто и когда его увидит;
  отказ не блокирует отправку.
- **Автоматической деанонимизации нет** — всё, что о себе сообщает человек, он сообщает сам.

> Контакты помощи в прототипе — примерные (112, 8-800-2000-122 и др.), уточняются с организаторами.

## Расширенные возможности (реализованы)

- **PWA + Web Push** без привязки к личности: приложение устанавливается (`manifest.webmanifest`,
  service worker), заявитель может включить push по конкретному обращению. Подписка привязана к обращению,
  а не к человеку; VAPID-ключи генерируются при старте (или задаются через env). Уведомления шлются при
  ответе специалиста/оператора.
- **ML-классификация** свободного текста: наивный байесовский классификатор (`internal/classifier`)
  обучается при старте на сид-наборе и подсказывает категорию оператору; словарная эвристика оставлена как фолбэк.
- **Realtime по WebSocket**: чат и карточка обновляются мгновенно через хаб комнат по обращению
  (`internal/realtime`), с авто-реконнектом на клиенте. Polling убран.
- **Шифрование способа связи at-rest**: контакт хранится зашифрованным AES-256-GCM
  (`internal/secretbox`), расшифровывается только при показе оператору по кризисному обращению.
- **Выгрузка XLSX** (и CSV): собственный генератор `.xlsx` без внешних зависимостей (`internal/xlsxwriter`),
  формат выбирается параметром `?format=xlsx`. В выгрузке только метаданные, без текстов.
- **Жёсткая блокировка одновременного ответа**: эксклюзивная блокировка карточки (`ticket_edit_lock`)
  на 30 секунд с авто-продлением; у остальных специалистов поле ввода заблокировано с указанием, кто отвечает.
- **Канал эскалации во внешнее реагирование**: оператор может эскалировать кризисное обращение
  (таблица `escalations`), генерируется одноразовый защищённый токен канала, запись в журнал; администратор
  видит список эскалаций и наличие оставленного контакта.

## Не реализовано (осознанно, за рамками MVP)

- **Полноценная интеграция с внешними/правоохранительными системами** — реализован механизм эскалации и
  одноразового защищённого канала внутри сервиса; сквозная передача во внешние ведомства — открытая задача ТЗ.
- **Промышленная доставка push** (собственный VAPID-ключ в секрете, ретеншн подписок, тихие уведомления) —
  в прототипе ключи генерируются при старте; для прод нужен постоянный ключ через env `VAPID_PUBLIC_KEY`/`VAPID_PRIVATE_KEY`.
- Обучение ML на реальном размеченном корпусе и оффлайн-дообучение — сейчас компактный сид-набор.
